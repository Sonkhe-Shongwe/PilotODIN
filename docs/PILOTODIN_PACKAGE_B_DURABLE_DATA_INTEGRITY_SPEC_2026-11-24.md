Primary documentation reviewed: [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html), [SQLite synchronous/journal semantics](https://www.sqlite.org/pragma.html#pragma_synchronous), [Python 3.11 os](https://docs.python.org/3.11/library/os.html#os.fsync), [Joblib persistence](https://joblib.readthedocs.io/en/latest/user_guide/persistence.html). Recovery truth table (process-crash coverage, not proven physical power-loss behavior):

- partial staging: retain/mark interrupted unless ownership and exact cleanup identity proven; never publish;

- committed receipt but missing/mismatched artifact, ambiguous reference, malformed ledger, missing permission, DB error: preserve everything and fail closed on affected use; never replace original or silently reset history;
- old path/legacy file not represented by ledger: never infer ownership or remove it.
Bound batches and receipt reads; allow privacy-safe diagnostic categories without exposing paths. Retain historical receipts; define any future pruning separately. Avoid holding SQLite write lock across parsing or full artifact serialization. Use real temporary SQLite and generated byte fixtures for interruption tests; explicit injected crash boundaries and subprocess exit where source-only authority permits. Verify startup twice, archive references, collision, commit-then-exception, disk-full/permission, malformed receipt, hardlink/reparse and missing source. ### Shared protocol and mechanism decisions

1. **SQLite is the authority for visibility; files are payloads.** SQLite [atomic commit](https://www.sqlite.org/atomiccommit.html), [transaction](https://www.sqlite.org/lang_transaction.html) and [isolation](https://www.sqlite.org/isolation.html) semantics cover database updates, not external files. Use explicit short BEGIN IMMEDIATE for intent, compare-and-set transitions and final business commit. No filesystem work or parsing while holding the final write lock except bounded identity recheck. A failed COMMIT may be ambiguous to the caller; close the connection and read authoritative state through a fresh managed connection before any cleanup. Preserve on doubt. Never retry a business commit blindly.
2. **No overwrite is enforced by the operation itself.** Python 3.11 [os.rename/os.replace and fsync](https://docs.python.org/3.11/library/os.html#os.rename) distinguish Windows rename (destination exists => failure) from POSIX rename (may replace a file), and os.replace intentionally replaces. A preflight existence check is not sufficient. Windows [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) has additional flags and cross-volume behavior; do not introduce Win32 FFI merely for B1. Select the portable exclusive final-file creation protocol below for B1. Its deliberate trade-off is a second bounded write, not an atomic filesystem rename. No hard-link publication (A's regular-single-link rule). No copy/delete fallback on collision.
3. **Durability is explicit and limited.** Flush and fsync each payload before cataloguing, verify the same file identity/size/digest after closing; on POSIX sync the admitted parent directory where supported before receipt commit. Windows Python fsync maps to MS _commit; do not infer directory metadata persistence or physical power-loss safety. SQLite [synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous) FULL/EXTRA and journal-mode semantics differ. Read actual connection PRAGMAs, require a durable normal journal and at least FULL synchronous for ledger-writing transactions (set on those connections outside transactions if required, never silently rewrite journal mode or certified FK policy); refuse unsupported unsafe settings. Preserve existing database migration and FK certification rules; do not make old databases certified merely by adding ledger tables. Source process interruption tests are not power-cut certification.
4. **Typed protocol, not a general transaction framework.** One small standard-library backend module (candidate backend/artifact_publication.py), plus storage schema/integration, typed kind-specific path and payload functions. Reuse existing workspace ownership/pins and per-write checks; validate generated names and regular single-link file identity independently even in the isolated unleased test seam. No arbitrary paths supplied to a generic recovery/delete routine. B1 implements dataset kind only; B2/B3/B5 add typed handlers after review, no unimplemented kind dispatch. Never store dataset contents, secrets or arbitrary absolute paths in ledger. Existing catalogue absolute path remains for compatibility.

### B1 schema and state machine

Add table artifact_publications_v1 with operation_id TEXT PRIMARY KEY (32 lowercase hex), kind TEXT NOT NULL (initially dataset), subject_id TEXT NOT NULL (reserved project ID), schema_version INTEGER NOT NULL CHECK=1, suffix TEXT NOT NULL (dataset .csv or .xlsx), expected_bytes INTEGER NOT NULL (1..40 MiB), sha256 TEXT NOT NULL (64 lowercase hex), state TEXT NOT NULL constrained to intent/staged/publishing/committed/interrupted/blocked, reason_code TEXT NULL (fixed enum only), created_at and updated_at UTC ISO timestamps NOT NULL. UNIQUE(kind,subject_id), index(state,operation_id). Both IDs application-generated; enforce exact shapes in application and schema where SQLite permits. No FK to a not-yet-created project; enforce relation at commit/recovery in the same transaction. Derive paths from operation ID and suffix: datasets/<operation_id><suffix>.uploading and datasets/<operation_id><suffix> (existing flat generated UUID layout); do not use DB-supplied path text as recovery authority. Keep schema additive and idempotent; check expected existing schema/version, fail closed on incompatible schema, no retroactive receipt creation. Kind-specific future payload tables keyed by operation_id may carry model manifests or export metadata without altering existing dataset semantics. No generic serialized arbitrary path JSON.

Legal transitions: intent -> staged -> publishing -> committed. Any nonterminal may become interrupted or blocked after fresh authoritative verification; committed is immutable historical publication fact and cannot be downgraded by cleanup or a later missing file. For later integrity issues use separate status/diagnostic (do not rewrite successful publication history). Interrupted/blocked never auto-resume or promote; no automatic reimport. CAS each transition using operation_id + previous state; a zero row update is a conflict, not success. Persist fixed reason categories (validation_failed, interrupted_before_commit, collision, unsafe_identity, reference_conflict, integrity_mismatch, storage_unavailable, unknown_commit); no exception text or private paths in receipt.

Exact B1 request sequence:
- Preserve HTTP 201 schema, filename display, 40 MiB body cap and current import preflight limits. Reserve IDs and compute digest of accepted upload bytes; commit intent before creating any publication file. Existing UploadFile spooling before application admission is bounded/request scratch, not published artifact; B5/C cover further scratch/admission issues.
- Create staging via xb, capture fstat identity, write, flush/fsync and close; revalidate regular file and retained datasets parent. Read staged bytes once with a hard 40 MiB+1 cap, verify length and digest, and parse from verified immutable bytes rather than reopening an arbitrary path. Refactor import_preflight and engine parser helpers to accept a reopenable read-only input abstraction (fresh BytesIO/TextIOWrapper per parse attempt), keep existing path call signatures as adapters, preserve CSV BOM/CP1252 fallback, identifier typing, XLSX member/expansion/shape caps and first worksheet rules. Reuse accepted upload bytes if exact staged digest and size agree; avoid retaining both full copies unnecessarily. Profile outside DB lock. Mark staged only after validation. No dataframe content in receipt.
- CAS staged -> publishing before final creation. Open generated final path with xb (atomic absence admission on both platforms), stream verified bytes in bounded chunks, fsync, close; compare original fstat to named identity and verify final size/digest before business commit. Do not copy by reopening an unverified staging name. B1 intentionally allows incomplete final *unreferenced* file after crash; the catalogue is the visibility barrier. 40 MiB limit bounds second copy; no overwrite even when a competing file appears after preflight. No os.replace or hardlinks. Existing final filename remains compatible.
- New storage publication commit function (keep save_project compatibility for audited fixture/metadata-only callers) receives reserved subject ID, verified final identity and validated profile. In one BEGIN IMMEDIATE transaction: verify receipt publishing and exact digest/size, ensure no existing project ID or catalogue path (including archived references, conservative path alias handling), insert projects, quality_state, quality_versions original, CAS receipt committed. No nested separate connections. Final path identity recheck immediately before commit, no long hash under lock. Return same response shape after known committed outcome. No new fake receipts for old imports or fixtures.
- After known successful commit, clean only request-owned staging identity under existing pins. If cleanup fails, retain staging and log fixed category; do not convert successful committed import into failure. On ordinary request failure, clean only files actually created by this invocation, with captured identities and fresh authoritative all-project reference and receipt check. Never touch a collision target, known committed final, unknown identity or ambiguous outcome. On commit-then-exception, reconcile exact receipt + project + Quality original; if proven success return normal response, otherwise report unconfirmed and retain bytes. No retry that creates a second record behind caller's back. Archived rows count as references. Legacy relink can change recorded path with existing exact digest authority: immutable publication receipt documents original publication, not permanent current path; never undo an approved relink or delete an old file based on obsolete location. B3 will extend explicit relink receipts if required.

Recovery runs from main._lifespan before recover_interrupted_experiments and before requests; real product/managed server already holds Package A process writer lease, explicit disposable in-process tests retain isolated seam. Do not reconcile from import-time schema creation or background request threads. Query indexed nonterminal receipts by keyset pages (128 rows); process bounded maximum 4096 per startup, fail closed with fixed diagnostic if exceeded rather than silently skipping. Recovery reads ledger and relevant catalogue including archived projects; do not hash every historical committed artifact at startup. For nonterminal with no reference and safe generated names classify interrupted, retain any staged or final bytes; if malformed, unsafe, conflicting, DB uncertain classify blocked where safe, otherwise fail startup. Do not delete files at startup in B1, even if they match a digest; digest does not prove ownership. A later explicit reviewed cleanup/backup operation may act only with proven identity. For committed data, existing Quality digest guards remain; add on-access receipt consistency check for ledger-owned projects without rejecting historically approved path relinks with matching original digest. Missing/mismatch blocks use, never replaces bytes or resets history. Legacy files without ledger are untouched. Recovery twice must be idempotent; committed records stay committed even if cleanup pending. Bound diagnostics, no raw paths.

### B2: artifact trust and memory

Existing requirements allow broad package ranges, so record actual Python major/minor and exact joblib, sklearn, numpy, scipy and pandas versions at production time, not requirements bounds. Keep familiar Joblib locally produced format; no new serializer dependency or automatic conversion. Store immutable typed manifest in SQLite anchored to experiment/project/quality version, source digest, canonical config hash, allowed model keys, per-file length/SHA256 and runtime versions; commit manifest + completed CAS in same transaction. Model key allowlist from engine CLASS_MODELS/REG_MODELS and ready result records; test_set.joblib mandatory. All other files rejected, no arbitrary manifest paths. Explicitly stage a generated directory beneath models, pin it; publish via exclusive final directory and exclusive files with verified byte copy (or Windows no-replace rename after releasing only staging pin, if exact scope review proves safe); never overwrite existing experiment. Directory partial state stays inaccessible through experiment status. Record manifest before publication, only mark complete after all hashes and final identity checks plus current cancellation and version recheck. Maintain original directory naming for committed models. Failure cleanup cannot delete possibly committed artifacts; existing ignore_errors rmtree is insufficient. Startup marks abandoned jobs failed, never promotes them or loads their files.

Deserialization: both choose_model loads and predict use one verifier. Validate receipt, manifest, current version, runtime compatibility, exact requested key/holdout, path safety and file identity. Stream verified bytes to a private bounded scratch snapshot under Package A owned backend-temp; hash during copying, require exact length, rewind same exclusive file object and joblib.load(file_object,mmap_mode=None). No hash-then-reopen path or externally mutable source stream; same snapshot handle only, cleanup after use. Trust boundary remains cooperating local product/OS user, not proof against attacker modifying database and artifact together or arbitrary process with same privileges. Default proposed initial admission caps 256 MiB per serialized file and 1 GiB aggregate per experiment, subject to pre-B2 source review of existing artifact bounds and synthetic resource regression; do not silently truncate or change successful model behavior. Disk-space check and current resource admission must precede snapshot; serialized size is not RAM bound, avoid loading all candidates. No claim of 8 GB physical acceptance. Missing legacy manifest: retain historical results, reports and selected metadata; refuse unverified binary load with controlled retraining guidance, no auto-hash or auto-retrain. ### B3: consistent backup and restore

Open source existing-only, create exclusive staged destination, use backup API to new target; integrity_check + foreign_key_check, record existing legacy violations without modifying originals, refuse certification if invalid. Inventory only audited owned roots and recorded references; verify relative names, sizes, SHA256, physical identity, source/version linkage, and exact model provenance. No secret-store or WebView/profile migration by default. Preserve root lock marker exclusion. Separate explicit user-chosen destination and review/confirmation; no path rewrite by basename; never restore over live workspace. Restore into fresh isolated destination, verify full manifest and DB references, then require separately approved migration/activation; no automatic switch. Retain current P1 exact-digest relink compatibility and backup receipts; any update to its mutation path requires source regression with disposable fixtures. No owner backup/restore authorised. Test rollback-journal and WAL fixture, missing data, invalid FK, path/link escape, collision, crash before final publication, corrupted manifest, archived histories and source unchanged.
