## Minimum independently defensible join for a future native writer investigation

The new \`qa/p4_research/n12_fileio_identity_join.py\` is an **inert source-only candidate schema**, not a replacement FileIO reducer or the governing N12 acceptance contract. The [adversarial synthetic tests](../tests/test_p4_n12_fileio_identity_join.py) use the real strict correlator to reproduce known-path completion chronology and refuse to promote it through a synthetic original-handle join.

A claim that a completed WebView2 write belongs to an original scoped process must, at minimum, establish:

1. **Process identity:** source-pinned executable, unique Sysmon process GUID and ETW PID/birth/sequence, original retained query handle with birth/exit corroboration, exact image and parent sequence. An ETW start/stop event or timestamp with matching PID **alone** is not enough. The existing separate native Stage 1 stop-time acceptance contract remains unchanged.
2. **Request and completion:** exact request time and ETW event ID 16, unique IRP and ID 24 completion with verified successful status, stable file-object/key identity where independently observable, and verified issuing-thread ownership. An accepted join requires original-handle birth before request and original-handle exit after completion, without a bare PID-reuse inference. This is a **deliberately conservative source-only reviewer**; Windows can legitimately complete I/O after process exit, in which case the strict capture can record the operation but the attribution's claim must remain **BLOCKED pending independent evidence** rather than silently discarding the mutation.
3. **Path provenance:** an independently observed open on the **same process-birth + FileObject** or a stable request-time FileKey name epoch, no name transition/reuse/ambiguous same-timestamp event, and a canonical permitted/protected/outside-scope classification. A stop-time rundown name alone is insufficient without the existing strict safeguards. Do not invent original paths, mask 113 outside-scope WebView-network writes or reclassify unsupported operations as nonmutating.
4. **Completeness:** verified ETW capture digest, whole relevant start/stop boundaries and loss counters, plus a positive transient write-and-restore observation; preserve protected endpoint checks and explicit unresolved rows. Procurement of independent trusted runtime evidence is future work.
5. **Privacy and authority:** public output uses fixed reason labels, not PIDs, SIDs, filenames, process command lines or original owner data; even fabricated perfect input returns \`REVIEWABLE_ONLY\` with \`process_to_write_provenance_verified: false\` and \`native_N12_acceptance: NOT_EVALUATED\`. An outside-scope path with a perfect join is still **outside-scope**, never permitted.
