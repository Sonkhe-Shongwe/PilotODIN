## Problem addressed
Issue #2 / BE-029 requests a user-visible distinction between consecutive saved report revisions, not merely a revision selector. Previously Deliver could reopen and export immutable snapshots but provided no explicit comparison of the saved title, narrative, verified evidence membership/order or dataset versions.

## Implemented in actual frontend
- [`reportRevisionComparison.ts`](../frontend/src/reportRevisionComparison.ts) is a pure read-only comparator of two already retrieved immutable saved snapshots of the **same report**, in strictly increasing revision order. It reports title and narrative edits, evidence added/removed/changed (including changed full frozen exhibit payloads), changed ordering of common surviving exhibits, added/removed dataset versions and snapshot content SHA-256 markers. A changed whole-report digest with no visible field differences is **not** falsely declared identical; it is flagged as other snapshot content changes.
- [`ReportWorkspace.tsx`](../frontend/src/ReportWorkspace.tsx) adds a **Compare with previous saved revision** button to Deliver for reports with an earlier revision. On click it fetches that specific prior revision through the existing authenticated read-only `GET /api/reports/{report_id}?revision={prior}` and compares it with the already opened selected immutable snapshot. Displays the changes in a responsive, readable panel. No report POST, recomputation, SQLite schema change, export, downloaded file, model or font is invoked by comparison.
- Comparison is explicitly limited to saved revisions, **not newer unsaved draft** changes; the UI warns when draft edits are present. Error display and loading state are local to comparison, not Save As. Requests are guarded by current project identity, current report-view generation and new independent comparison ticket. Project change, Explore evidence handoff, open different report/revision and Save invalidate stale comparison results. Earlier native Save As/draft and preview guards stay separate.
- [`reportComposerGate.ts`](../frontend/src/reportComposerGate.ts) introduces independent `beginComparison/isCurrentComparison/invalidateComparison`; `invalidateAll` also invalidates comparisons. Existing draft/save and preview safety semantics are not changed.
- [`report-workspace.css`](../frontend/src/report-workspace.css) adds bounded responsive presentation and readable wrapped narrative/digest text. Report data is escaped by React text rendering, not interpreted as active HTML.
