# P4 R02.5 | Same-capture transient mutation and generated calibration controls on no-CDP FileIO

**21 November 2026 | Implemented in SOURCE and validated with generated/mocked regressions. NO native PilotODIN/WebView2 execution or containment acceptance.**

## Existing source reused and exact scope

The pre-existing full N12 journey already had (a) the **calibration-first and calibration-last** process/TCP/UDP/file fixtures, and (b) the generated **write-and-restore** fixture that changes and restores bytes while both full snapshots fall inside ETW. The guarded no-CDP full Kernel-File path lacked those controls. The source change reuses **\`qa.p4_research.n12_app_journey.run_initial_calibration\`**, **\`calibrate\`**, **\`verify_fixture_sysmon\`**, **\`qa.p4_native.n12_protected_restore.exercise_restore\`**, and **\`same_capture_restore_evidence\`**. It does not alter their original strict comparison semantics.

[Final source commit \`964a63c\`](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/964a63c2cf6c4f10df9de265bc2285fbe29534db) contains the integrated source and regression checks, including ETW-loss adversaries.

### Native path behaviour, if separately approved later

1. The already default-off and independently consent-gated \`n12_app_lifetime --no-cdp --fileio\` controller requires the existing original-child-handle private pipe, exact source and binary, Windows hosted runner, and first-run restrictions BEFORE it creates a capture or launches an app. Existing native full-app workflows are disabled.
2. Under its disposable \`RUNNER_TEMP\` journey root it creates **only** a generated \`write-restore-control.bin\` with a known baseline. This path is placed in \`observed_roots\` and \`immutable_observed\`, **not** added to a permitted writable root. Thus generated protected-control writes remain visible to the original strict reducer and are not secretly suppressed.
3. The original Kernel-File + Kernel-Process ETW capture brackets the complete first protected snapshot, a **generated initial Sysmon/file/TCP/UDP calibration**, the normal no-CDP real app startup, readiness and graceful close, then the generated write/restore fixture and final calibration, and the complete final protected snapshot. All generated control writes occur while the same ETW session is live.
4. Exact final bytes/digest must match the known original, but **matching endpoints by themselves are insufficient**. The same digest-verified ETW export is checked with the already tested \`same_capture_restore_evidence\` / \`inspect_restore_writes\` and \`file_lifetime_report\`. Both stage writers must have bounded lifetimes, unique successful FileObject/IRP write completion, request-time canonical path and no conflicting extra write.
5. The no-CDP redacted FileIO reviewer now binds the generated calibrator root processes as \`calibration\` separately from actual \`webview\` and \`webview-network\` roles. It applies the original \`trace.calibration_window\` checks for child process/file rename/create/write/resize/delete and TCP/UDP loopback markers, requiring before/after windows to bracket app launch/profile-exit. Missing Sysmon, FileIO, network, stage order or event coverage keeps the calibration **BLOCKED**.
6. **Zero reported ETW event/buffer loss and nonempty capture buffers** are necessary for either generated control's positive diagnostic status. If loss is reported, neither control is considered corroborated, even if a synthetic/mock positive status is supplied by a subordinate checker. Raw original PID, GUID, paths and timestamps are not published.
7. The source-only fixed-label outcome at best is \`calibration_and_transient_write_proof: SOURCE_ONLY_CONTROL_REVIEWABLE\`, with \`same_capture_write_restore: TWO_UNIQUE_WRITES_CORROBORATED\` and \`generated_calibration_bookends: BOOKEND_OS_FILE_NETWORK_REVIEWABLE\`. **No native acceptance:** \`status: BLOCKED\`, \`file_mutation_acceptance: NOT_EVALUATED\`, \`native_N12_acceptance: NOT_EVALUATED\`, \`effective_webview_user_data_folder: NOT_VERIFIED\`, and \`full_product_tree_mutation_containment: NOT_DEMONSTRATED\`. This does not bypass actual prohibited write counts, missing path credits or child handle coverage gaps.
