## BE-028 | Evidence composition: separate implemented core from optional advanced depth

**Already implemented in production source (not hypothetical):**
1. `reports._collect` resolves project-scoped, integrity-checked completed investigation, saved Explore `explore_snapshot`, selected and held-out-evaluated `model_evaluation`, and explicit read-only `quality_audit` artifacts, then freezes ordered evidence in an immutable SHA-256 report revision.
2. `_model_evidence` projects selected model/target/split, held-out task metrics, baseline/CV and bounded classification per-class diagnostics; excludes raw held-out predictions/row values and failed/non-selected models. `_quality_evidence` stores bounded quality findings and correction history by dataset version. Saved Explore snapshots are configuration-hash checked.
3. `ReportWorkspace` can select, reorder, preview bounded *verified facts* (not raw observations), choose an analyst-written outline, save and reopen a revision, inspect HTML, compare revisions, and export version-bound HTML/PDF. These functions are real current source and partly backed by earlier scoped test evidence.

**Residual currently NOT accepted as a complete 1.0 capability:** richer fully typed advanced visual scorecards (for example full confusion-matrix visualization and deeper model Quality interactions), rich cross-evidence drill-down and arbitrary chart editing inside the report. Existing typed scalar metrics and class diagnostics should **not** be misrepresented as absent; neither do they prove every aspirational high-end interactive feature. Possible consequence of deferral: initial 1.0 can export grounded model/Quality/Explore evidence but will not provide the same advanced analytical presentation/editorial depth as a dedicated BI/report authoring platform. These are **feature-depth/UX gaps**, not newly reproduced numerical corruption or project-boundary breaches in this review.

**Recommended owner choice:** Retain completed verified scalar/model/Quality/Explore report evidence as **mandatory bounded P2 core**; treat additional rich visuals and cross-source editing as a **separately inventoried future enhancement**, only if explicitly approved against the original 1.0 blueprint obligations.
