# PilotODIN P2 | Idempotent saved report revisions

**Date:** 5 November 2026  
**Primary phase:** P2 ACTIVE / REVIEW_REQUIRED  
**Branch:** `feature/live-dev-workspace-20261023`

## Confirmed problem and scope
Build E QA Issue #2 / BE-029 reported that pressing Save again with identical canonical report content created a new immutable revision instead of truthfully reporting no changes. The existing `backend/reports.py::save` always inserted `report_revisions_v1`, even when the submitted report's title, narrative, complete evidence and dataset-version projection matched the latest saved snapshot exactly. Stale Save success notices could also remain on-screen after opening a different historical revision.

This P2 correction fixes revision idempotency through **real FastAPI and SQLite** plus a bounded Deliver UI notification improvement. No protected user project, installed Windows executable, model, font, installer or existing approved revision was altered.

## Production implementation
1. [`14227db9d772`](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/14227db9d77248c8e882dc575d2e58e62d3be897): `backend/reports.py::save` uses the existing `BEGIN IMMEDIATE` transaction and checks the **latest canonical snapshot AND SHA-256** before attempting another revision insert. Identical input is returned as the same revision with `unchanged=true`; no new row is written. Different narrative, title or evidence order creates an independently numbered new revision. The existing `reports.load` integrity and project-scope checks remain in place. The no-op path calls `load` for that exact revision; source project lifecycle write admission is still checked first.
2. [`8b9d274e5845`](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/8b9d274e5845432f497d5cd841a748ed212e48c2): `POST /api/reports/{id}/revisions` returns HTTP **200** when no new immutable revision was created, otherwise retains HTTP **201** for a new revision. First report creation still returns **201**.
3. [`20fb50cd778f`](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/20fb50cd778fbdc99a8a72e9cfe37aff79d596a6): Deliver editor recognises `unchanged` and truthfully displays **No changes to save** while preserving notice of newer draft edits that were not submitted. Opening another saved report and editing a draft clears stale prior Save notices. The existing saved-report immutable revisions and export content remain unchanged.
