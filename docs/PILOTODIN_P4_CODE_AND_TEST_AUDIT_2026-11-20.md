## Why the jobs failed

The recent one-file jobs exercise collectors against a generated Python process. They never open PilotODIN. The first timing run matched the writer and file, then found the Procmon timestamp outside the child's measured open interval. The follow-up stopped at ETW process start matching before it could test either clock. A third identical attempt would still conflate missing events, multiple matches and births that fall outside the matcher. These are measurement failures. The separate Windows app journey also had actual filesystem and network policy failures.

## Test and maintenance defects

- Generated rows designed to align can verify reducer behavior, parser boundaries and fail-closed logic. They cannot verify live collector clock agreement, event delivery or capture completeness. The latest two-clock reducer stops at its first ambiguous identity and retains no fixture replay evidence. A future authorized fixture should preserve bounded, sanitized counts and relative ticks on failure, with the role and reason, before computing a combined verdict. [Reducer order](../qa/p4_research/n12_procmon_timing_control.py#L96) · [Timing tests](../tests/test_p4_n12_procmon_environment_control.py)
- Data-safety tests exercise catchable staging failures, stale state already present before a request, and consent at provider selection. The new probes exercised process interruption between commits, state changing after prechecks, and the actual payload after routing. Test those boundaries using barriers or injected failures so that each case is deterministic. The existing Quality receipt and report redaction cases provide patterns. [Upload tests](../tests/test_p1_upload_atomic_staging.py) · [Provider tests](../tests/test_hybrid_local_ai.py) · [Report evidence](../tests/test_a4_model_evidence_reports.py)
- The full audit uses a shared set of calibration issues to block otherwise passing file and network verdicts. Keep the combined acceptance gate, and show which checks are independently observed, failed or unverified, including shared identity and loss checks. A file-only failure should remain legible in the network report. [Combined reducer](../qa/p4_native/n12_trace.py#L1111)
- The ETW correlation function spans 786 lines and the app-journey capture function spans 250. The API entry module spans 1,474 lines. The actionable issue is mixed responsibilities: event decoding, matching and escalation of evidence status in the harness, and routing, state transition and evidence projection in the backend. Extract or reuse small boundaries when fixing a verified bug. A broad rewrite would spend time recovering existing behavior and evidence. [Correlation](../qa/p4_native/n12_etw_correlate.py) · [App driver](../qa/p4_research/n12_app_journey.py) · [API](../backend/main.py)
- Since the WebView retest record `21c89088`, there were 76 commits through the audit baseline. Of those, 45 touched `qa`, 37 touched `.github/workflows`, and only three touched `backend` or `frontend`, two of which changed QA pages. These counts overlap and measure where edits landed. Recent changes were concentrated on the evidence apparatus while core regression scenarios still had holes. [WebView retest baseline](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/21c89088) · [19 November process audit](./WORK_AND_PROCESS_AUDIT_2026-11-19.md)

## Direction and decision checkpoints

1. **Correct the cloud payload first.** The next decision changes when the exact serialized outbound payload contains only approved aggregate fields while the local Evaluate view still exposes its established evidence. Verify locally with generated data before relevant routine CI. Follow with atomic import publication, archive and selection fences, then export durability. Give each fix a regression that fails on this audit baseline and passes after the change.
2. **Pause the one-file clock chain and prepare a representative Windows app journey.** In the existing calibrated design, use ETW for file writes and process lifetimes. Use Procmon launch metadata only for specific positive corroboration when identity is independently verifiable. Before requesting an approved run, show that the prepared reducer can report writer and destination evidence, missing attribution, and calibration separately. The run should exercise import, a reviewed Quality change and undo, close and reopen, check protected file bytes, and positively detect an in-window write restored to its original contents. Preserve exact source, binary and sanitized failure-stage evidence. Attribute the WebView temp creates, or report them as unresolved and hold the gate. The official R02.5 requires complete calibrated filesystem acceptance, and R02.6 still requires startup-to-exit network isolation. [Governing worklist](./P4_80_ACCEPTANCE_WORKLIST_AND_EVIDENCE_INTAKE_2026-11-12.md) · [Prior handoff and diagnostic proposal](https://github.com/Sonkhe-Shongwe/PilotODIN/blob/577447964c09a44173028b0dd28211fc0766c342/docs/SESSION_HANDOFF_CURRENT.md#the-two-clock-run-blocked-at-etw-process-start-matching)
3. **Keep the physical and original-data decisions separate.** The verified Local analytics fallback is a useful milestone. Full offline inference needs a candidate that can run at ordinary 8 GB laptop headroom and coexist with the app. The original-data incident remains a historical strict fail with 74 differences and unknown writer. Matching protected endpoints on a disposable hosted run does not resolve that incident. Prospective preservation still requires separately approved owner-device evidence.
