## User need and bounded requirement
QA Issue #2, BE-028, requested guided authored reporting sections and clearer interpretation support. Deliver already collects verified, project-scoped selected evidence; raw values must not be invented by AI or templates, and the saved narrative is explicitly analyst-authored. This increment adds **three optional, explicitly chosen, human-written outlines** without altering backend report storage, evidence verification, frozen SHA-256, source datasets, default HTML/PDF export or installed app resources.

## Actual production implementation
- [`frontend/src/reportDraftOutline.ts`](../frontend/src/reportDraftOutline.ts) defines three grounded structural choices:
  1. **General analysis:** Purpose and decision; Verified evidence interpretation; Limitations and uncertainty; Recommendations and next steps.
  2. **Data quality review:** Purpose of quality review; Verified quality findings; Reviewed treatment decisions; Limitations and follow-up.
  3. **Model evaluation:** Prediction objective; Held-out evaluation interpretation; Model reliability and limitations; Recommended validation.
- The helper produces **plain section headings only**. It writes no statistics, confidence claims, advice, autogenerated model interpretation, evidence IDs, source samples, or plausible placeholder values. The same existing analyst narrative string is used by the immutable revision backend and HTML/PDF. The newly added optional client-side completion checklist is not a backend schema or new report field.
- [`frontend/src/ReportWorkspace.tsx`](../frontend/src/ReportWorkspace.tsx) adds **Use [outline] outline** actions and a visible completed-section checklist. An outline can be inserted only if the current narrative is empty/whitespace and no report write is pending. It participates in `onDraftEdit()` epoch, so an in-flight old draft/export cannot silently replace authored content. An incomplete **active guided outline** disables Save, and the save handler also explicitly checks completion before POST. Required headings must appear exactly once, with nonempty human-authored text under each; missing/duplicate heading or blank section is incomplete. Users can explicitly **Use freeform writing (keep my text)** at any stage, which clears the optional outline checklist but does not delete or rewrite their text.
- Opening a saved revision, creating a new report, changing projects and accepting an Explore evidence handoff clears the optional template selection. Historic stored narrative remains untouched and is never retrospectively checked as a template. Existing report writer/read gates, evidence selection and immutable revision data shape are unchanged.
- [`frontend/src/report-workspace.css`](../frontend/src/report-workspace.css) provides compact responsive, focus-visible and readable guidance; no external assets, extra model, network service or font dependency.
