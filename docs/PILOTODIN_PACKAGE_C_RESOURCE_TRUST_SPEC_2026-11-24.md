## 1. Objective and evidence boundary

Preserve local-first analytics, data and report integrity, explicit consent, current projects and settings, offline use, navigation responsiveness, deterministic fallback, version-bound computation and existing hard limits. On target 8 GB Windows hardware the blueprint requires initially one heavy job, AI yielding to data/ML, truthful queue/checkpoint and no silent cloud transition after bundled inference fails. W07/E-02 remain physical acceptance tests; W01 requires pinned build inputs. No technology rewrite, database migration, new installer, external service or arbitrary model selection. Existing Python/FastAPI, Rust/Tauri, React, SQLite retained.

[Resource-aware mode evidence](./RESOURCE_AWARE_MODE_DESIGN.md): previous isolated everyday Local analytics 735.27 MiB sampled combined working set, model unloaded, not a combined-load proof; planning envelope roughly 1–3 GiB resident app RAM, not a hard guarantee. 0.75 GiB current training/model-load and 2.00 GiB local inference free-memory screens are heuristics; 1.50 GiB R03 candidate was deferred on physical laptop and is not production default. B4 exact generated CSV capacity test and B5 75 MiB writer/export caps are not end-to-end worst-case RAM guarantees. Preserve 40 MiB input, row/column/cell, encoded-matrix, provider prompt, export and report bounds; smallest limit wins. Never add estimated available RAM to process working sets or call an OS snapshot a reservation.

## 3. C1: one authoritative workload reservation

### C-D01 decision: owner and scope

**Selected:** one small process-local admission coordinator in the exclusively owned Python analytical engine, with an authenticated/owned native supervisor grant bridge. All heavy workload starts use one atomic lane in every mode; existing SQLite fitting slot is additional durable protection, not replaced. Owner is the coordinator instance tied to current engine session, not UI, client preflight, per-route locks or a saved preference. No independent Rust "allow" decision can substitute for a grant. Keep read-only status and cancellation responsive. Rejected: independent memory checks (race), global queue framework/Redis (extra dependency/service), coarse DB writer lock around computation (blocks unrelated metadata and threatens A/B), global OS process manipulation (outside authority). Initial serialization is conservative; future concurrency only with measured evidence and approved behavioral change.

**Admission policy:** retain saved adaptive/low_memory/performance IDs and existing hard bounds. All modes enforce one heavy lane and a fresh valid memory observation before a new heavy start. Provisional common floor 0.75 GiB for data/parse/replay/training/model load/export/report work and 2.00 GiB for inference cold start/generation; never lower existing floors; operation-specific tighter caps remain. These are screening minima, not predicted peaks. Unknown/invalid observation defers heavy work; health, metadata, cancel, safe cleanup and lightweight UI remain accessible. Adaptation may adjust scheduling/presentation only, not bypass cap. Keep isolated R03 exception exact and explicitly labelled; do not silently apply candidate 1.50 GiB. Validate refusal wording/modes and preserved behavior against prior tests; changing approved hardware or functionality needs owner decision, not guessed thresholds. Do not mark a denied operation queued unless a real bounded queue/checkpoint exists.

### Reservation contract and route/lifetime matrix

Use typed fixed classes, generated opaque operation ID, generation/session, exact owner, monotonic start/deadline, state (idle/reserved/running/draining/released/blocked), idempotent matching release and denial categories busy/memory_unavailable/headroom/stale/shutting_down/ownership_unknown. One atomic admission decision under short coordinator mutex; no long work or wait while holding mutex or DB transaction. Grant is scoped to one operation, never transferable by browser. Nested helpers accept internal owned lease, do not reacquire or trust request-provided flags. Generation check makes stale release harmless. Release in finally only when actual owned worker/stream/cleanup completes; cancellation/timeout is not evidence work ended. No force release/TTL eviction of live or uncertain worker. Release no-op duplicate with same generation only; record unknown as blocked until safe reconciliation. No durable RAM lease inferred from file/DB status; preserve existing durable task/receipt recovery.

### C-D02 cross-process bridge decision and gate

Reuse existing host-owned engine stdin and sidecar event channel as preferred control transport: no new port, dependency, shared untrusted UI capability or ad hoc HTTP client. Existing STOP semantics/EOF fail-closed remain. Add versioned bounded typed control frames only after compatibility review, fixed commands GRANT_REQUEST/GRANT_REPLY/RELEASE/DRAIN and STOP; max 4 KiB frame, exact type/schema, single outstanding host control request, request ID + launch generation + non-browser capability, bounded response and no paths/prompt/secret in logs. Host-only channel/capability must not appear in BackendConnection, Tauri IPC return or arbitrary user input. Parser handles split/coalesced frames, rejects oversized/unknown/duplicate/stale frames; preserve log separation and stop on malformed control frame, bounded stop/EOF. A granted inference lease covers verifying, spawning, active generation and resident worker until confirmed exit (sleep-idle is not proven reclamation). Rust owner must recheck engine generation/stopping immediately before spawn; backend cannot clear native grant from a frontend assertion or mere timer. If engine dies, no new engine launch until previous owned inference exit confirmed; old generation cannot release new grant. If grant/reply lost, refuse new work and reconcile owned process, never spawn twice. No locking across OS process waits; event listener needs access independent of launch gate. A bounded control handshake timeout must not authorize retry of an unknown grant.

If exact locked shell cannot reliably separate/transport bounded control frames and stop events, stop at bridge compatibility blocker, not parallel unsynchronized guards. Review alternative host-only authenticated loopback broker on existing port with existing reviewed dependency or fixed byte-lock only after proving identity, lifetime, drain and cross-process semantics. No unreviewed new crate, custom HTTP parser or raw global lock-file protocol; no source closure based on mock bridge alone. C1 implements authoritative ownership contract and host admission seam before C2 changes scheduler/launcher; C2 completes async integration. Keep C1 source readiness vs closure evidence distinct; if C1 needs exact C2 host integration to establish required behavior, count it open until that evidence exists rather than inventing partial credit.

### C-D03 priority and truthful waiting

Data/ML has priority over new inference when waiting, but do not kill active generation or training to simulate priority. Native resident inference stops at idle or safe completed step when data requests drain; block new inference, request owned group termination, retain grant until actual exit witness. A data request can receive retryable draining state, never "running" before grant. AI requests during heavy work use existing durable autonomy step boundary or a bounded user-visible pending request: at most one pending direct AI intent per active project/host, expiry/cancel, version/config recheck, no implicit new network or replay of mutation. Other requests return retryable busy; no unbounded queue, no stored raw prompts/frames. User can choose verified deterministic local result if available without another heavy calculation; otherwise truthful resource-deferred response. Keep task/UI state explicit. Avoid acquiring inference lane while holding data lease: stage bounded verified context, release data resources, then start generation with same immutable version/context correlation; recheck before publishing result and discard stale completion. Existing frontend invoke-before-POST flow must be changed in coordinated source steps, not left as a bypass. Measure interactive latency and yield behavior later; no arbitrary estimate of sleep memory release.

## 4. C2: asynchronous single-flight inference

**C-D04 decision:** use existing Tauri async command + spawn_blocking for file verification, owned launch and blocking waits, not synchronous main-thread work or unbounded spawn per click. Single-flight state idle -> requested -> verifying -> launching -> ready -> draining -> stopped/failed/blocked; generation ID and join/exit witness; one owned worker and one startup job, duplicate request returns current state or joins same attempt, never launches twice. Keep short state locks only; no mutex or launch gate across hash/read/async await. Final gate rechecks main window, same current engine, stopping, grant, admitted storage, manifest/bytes and resource state before spawn. Existing per-session inference token, fixed alias, 2048 ctx, 2 threads, parallel 1, CPU-only, fixed loopback port, no model download and current runtime directory preserved. Validate manifest path/size/hash and exact runtime inputs; no weaken B2/B5 trust. Keep hash on owned immutable observation; verify source/identity before spawn, no unsafe cache by filename; C5 provides independent build provenance, not hostile filesystem proof.

Cancellation signals generation owner, cooperative hash chunk check and safe step; abort of blocking task does not stop actual work. No ready on spawn alone: backend bounded health/model identity probe and exact generation. On child error/exit, release only matching grant after confirmed termination; shutdown drains known jobs, refuses graceful certification while unknown. Existing stop_owned_workers gate and dataset-save lease preserved. Frontend status/launch errors privacy-safe, no cloud fallback or fake progress. Ordinary UI responsiveness checks under fake hash/spawn and controlled barrier; native code compile/test only after separate approval, ideally combined reviewed C1/C2 scope rather than a chain of micro-runs. No actual model launch now.

## C1 upload refinement: bounded envelope and parser ownership

Keep the existing 40 MiB exact file cap, with at most 1 MiB additional multipart framing (41 MiB total streamed envelope, smallest applicable limit wins). Admit DATA before parser/read, require exactly one file part named `file` and no extra form fields (current create_project signature), reject malformed/duplicate Content-Length and compare declared length to actual bytes where present. Count bytes incrementally without buffering the whole request; missing length does not waive the cap. Envelope and one-part restriction are defensive protocol limits, not physical RAM proof; verify existing browser multipart compatibility before activation.

## C1 training refinement: reservation and worker lifetime

Current `new_experiment` materializes and validates the frame before its existing policy screen, creates a queued record via `new_experiment_with_capacity`, then registers a synchronous FastAPI BackgroundTasks callback. `claim_queued_experiment` is CAS queued→running; terminal setters only modify running; startup recovery marks all unfinished work and is not an appropriate request-level cleanup. A staged request owner holds a RESERVED training lease before materialization, without marking the worker running. Once the exact queued ID and callbacks are bound, transfer to an identity-distinct worker lease; retain it until actual callback return and confirmed terminal durable state, or confirmed exact queued-only settlement when no worker ever started. The outer ASGI lifetime must finalize the request even on failed response delivery. Use a short lock to exclude late callbacks after unstarted settlement starts; do not hold it across DB or work. A running callback is never settled as unstarted. Ambiguous queue publication, failed terminal check or uncertain unwind retains a blocked lane. The existing SQLite slot/claim, cancellation, version and artifact protections remain unchanged.
