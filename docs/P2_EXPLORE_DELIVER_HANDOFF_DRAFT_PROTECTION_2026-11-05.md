# PilotODIN P2 | Explore-to-Deliver evidence handoff and unsaved Deliver exit safety

**Date:** 5 November 2026  
**Branch:** `feature/live-dev-workspace-20261023`  
**Status:** P2 ACTIVE / REVIEW_REQUIRED; P1 CLOSED for development; P8 installed/offline release NOT CERTIFIED.

## Confirmed source risks

1. A new `preselectEvidenceId` previously entered `ReportWorkspace` through an effect that immediately invalidated pending reads and cleared report title, narrative, selected evidence and loaded revision, without consulting the just-added New/Open local draft-discard guard. If a future mounted component received new preselection while dirty, it could silently destroy unsaved authored text.
2. The primary Studio's memory-only unsaved marker was wired to Prepare, Model and Predict, **not Deliver**. Unlike those legacy panes, Deliver unmounts as soon as the primary stage changes, including switching to Explore. Existing shell navigation and reload/close guards could therefore miss an unfinished report.
3. `App` previously queued the `deliverEvidenceId` **before** attempting to navigate from Explore to Deliver. A rejected primary route could leave an unconsumed selection queued for a later unrelated Deliver visit.

## Production corrections

- `frontend/src/ReportWorkspace.tsx`: Verify that the incoming ID is in the active project-scoped eligible evidence catalogue **before** proposing any change. If a report write is pending, refuse without overwriting. If title, human narrative or selected evidence differ from the original baseline, show the existing accessible, explicit **Keep editing / Discard and continue** dialog as a new `handoff` action. Keep/Escape preserves all existing content, while only explicit Discard invokes the extracted `applyEvidenceHandoff` reset. The exact incoming ID is marked consumed for that mounted project to prevent a cancelled handoff from unexpectedly reappearing on catalogue refresh. Applying it retains the preexisting stale-open/view invalidation, historical evidence notice and saved evidence provenance check. The callback reports **only a boolean unsaved indicator**, not text or evidence values, to the primary shell.
- `frontend/src/App.tsx`: Primary Deliver signals `onPrimaryDraftEdited('deliver')` when dirty and `onPrimaryDraftCleared('deliver')` when a successful Save, reload or deliberate draft reset leaves the actual view clean. `go(next)` now returns its approval result. Explore queues `deliverEvidenceId` **only after** `go('deliver')` accepts, rather than before a veto.
- `frontend/src/primaryStudioExitGuard.ts` + `frontend/src/UnifiedShell.tsx`: A dirty Deliver primary view requires existing shell consent on any exit to a different workspace, not only on exit to Canvas. All internal Studio, rail, tab, history navigation and tab-close approval entry points use the updated marker check; tab close pre-approval is tied to the actual destination, not the tab being closed. For legacy Prepare/Model/Predict, the old Canvas-only behavior is intentionally preserved. Dirty Deliver is included in the existing native close/browser reload marker and owner Windows project-switch consent policy through `dockInputDiscardGuard.ts`. The marker is cleared only for the matching project and view. No report content is stored or transmitted in shell markers.
- Only existing project-scoped verified evidence GETs and view state are affected. No backend data/SQLite schema, Quality action, frozen saved report, render_html/pdf, ReportLab font or sidecar installer was modified.
