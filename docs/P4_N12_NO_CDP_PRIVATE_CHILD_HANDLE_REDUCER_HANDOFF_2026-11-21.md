## Exact source-only code change

- `qa/p4_research/n12_no_cdp_child_handles.py` introduces a private-only `PrivateChildHandleEvidence` frozen bundle with **source SHA, executable SHA-256, original app-handle birth ticks, sampling start/finish ticks, private retained original child handles and the diagnostic collector receipt**.
- The new `private_child_handle_diagnostic` wrapper compares source/binary provenance to the **actual capture manifest**; root creation to the **original retained Windows app handle**; and sample times to **capture start, launch, app creation, ready, close, profile-exit and capture end**. A child may be credited in this shadow design only when its retained-handle creation and exit fall in the captured sampling/profile interval. It rejects unavailable/misordered markers, invalid inventory, wrong source, wrong app-handle root or missing source evidence with fixed, redacted failure labels. No raw identifiers, absolute FILETIMEs or executable paths enter this diagnostic result.
- `qa/p4_research/n12_app_lifetime.py::reduction` now accepts optional **in-memory** `child_handle_evidence=None`, **only** in `no_cdp_profile=True`. When a unique legitimate Sysmon app/worker and an ETW event source are present, the reduction derives `no_cdp_private_child_handle_diagnostic` before the original strict `find()` can fail. With no bundle it explicitly returns `NOT_EVALUATED`; with a complete synthetic bundle it may return `REVIEWABLE_ONLY` and per-role counts; every malformed, missing or inconsistent bundle returns `BLOCKED`. **Every receipt contains `native_N12_acceptance=NOT_EVALUATED`.**
