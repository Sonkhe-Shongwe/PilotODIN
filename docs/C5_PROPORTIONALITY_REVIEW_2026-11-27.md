This is a finite alternative development evidence method. It genuinely reduces assurance against compromised GitHub provider/image/setup action, malicious compiler/interpreter or installation transformation: a compromised trusted bootstrap could falsify test and checksum outputs. Standard hash checking also cannot establish that an intentionally malicious pinned dependency is safe. Mitigate through reviewed immutable actions, exact compatible versions and origins, limited permissions, ephemeral clean runners, no secrets/owner data, no untrusted PR execution, no persisted checkout credentials, controlled scripts and no distribution of CI binaries, actual package checks and retained test evidence. Native/release consumed-input provenance and actual product isolation remain separately mandatory, not certified by this method. No zero-risk assertion.

External engineering references (design support, not proof of PilotODIN compliance): [pip secure installs](https://pip.pypa.io/en/stable/topics/secure-installs/) describes hash-checking mode, [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use) recommends immutable SHA pins and permissions hardening, [SLSA Build Track v1.2](https://slsa.dev/spec/v1.2/build-track-basics) distinguishes different assurance levels and hosted provenance. None mandates the proposed project risk decision or certifies this repo.
