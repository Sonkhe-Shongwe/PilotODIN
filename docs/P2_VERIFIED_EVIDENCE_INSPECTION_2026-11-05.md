## Confirmed product gap and solution
Issue #2 BE-028 documents that Deliver offered only an operation label, source dataset version, params and abbreviated evidence ID when selecting an evidence exhibit. This made it difficult to distinguish verifiable figures before drafting a report.

**Implemented:** Each eligible evidence item now offers a separately focusable **Inspect facts** button. This opens a compact, read-only panel of at most **eight scalar aggregate facts** from the **same backend evidence verifier** used to compose immutable reports. The panel shows source operation, trusted evidence ID, current and source dataset versions, warnings when historical, up to eight key-value fact entries, optional bounded source note, a factual omission count, and a disclosure that raw rows, predictions and complete evidence details are not shown. Inspecting never selects the evidence, recalculates an analysis, captures Quality, saves a report, rewrites a dataset or initiates an export. A source with no eligible scalar facts is truthfully identified as such, rather than displaying invented metrics.

**Scope and source:**
- `backend/reports.py::evidence_preview(project_id,evidence_id)`: validates exact 32-character hex evidence IDs and project existence; uses `_collect` for the actual **project-scoped**, evidence-completeness and integrity-checked source, then projects only bounded scalar summary fields and a short note. The 8-fact, 80-character key, 140-character value and 240-character note bounds avoid exposing full evidence `data`, `findings`, raw source records or held-out per-row predictions. Returns `additional_summary_facts` and a history warning based on the current Quality version, without recomputation.
- `backend/main.py`: one read-only `GET /api/projects/{project_id}/report-evidence/{evidence_id}/preview` endpoint, reusing report HTTP error semantics.
- `frontend/src/ReportWorkspace.tsx`: a distinct **Inspect facts** button outside checkbox labels, with accessible labelled section, loading/error/close states and clear historical evidence warning. The existing report checkbox, order, Save, PDF/HTML export and Quality capture semantics are preserved. Source identity and project are checked before showing an HTTP result, and new project/report navigation clears preview.
- `frontend/src/reportComposerGate.ts`: separate `beginEvidenceInspection/isCurrentEvidenceInspection/invalidateEvidenceInspection` epoch to discard stale results without invalidating report save, export, comparison and HTML preview channels. `invalidateAll` also invalidates inspection.
- `frontend/src/report-workspace.css`: separate button with focus-visible indicator, readable bounded responsive aggregate fact layout.

## Limitations, follow-up and prohibited inferences
- This is a **bounded scalar-fact review**, not a complete interactive drill-down or an exhaustive raw evidence/data preview. No raw record page, per-row model prediction, data values or source excerpt is returned. The backend verifier used for saving reports is applied to live eligible evidence; the *full immutable revision evidence* remains created only on explicit Save.
- No physical owner Windows/WebView2 evidence-inspection interaction was separately observed. A successful hosted Linux browser test and frontend source build do not certify the installed Windows app or release.
- P2 is **ACTIVE/REVIEW_REQUIRED**. Normal Unicode PDF activation still requires independent approval of three original unchanged Noto fonts, three original OFL notices and all six final SHA-256/face/Reserved Font Name/release distribution checks.
