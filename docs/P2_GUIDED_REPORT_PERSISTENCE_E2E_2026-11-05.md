## Implementation / safety boundary
- Added [`frontend/e2e/p2-real-http-guided-report-persistence.spec.ts`](../frontend/e2e/p2-real-http-guided-report-persistence.spec.ts) to the **existing dedicated GitHub-owned test workflow**. The CI runner uses a fresh temporary `PILOTODIN_HOME`, one owned disposable Uvicorn child process on `127.0.0.1:8000`, and one local Vite/Chromium browser on `127.0.0.1:5178`. It refuses local/non-GitHub execution and stops **only its owned child**. No live owner dataset, workspace, installed app, font file, model or sidecar is used.
- The independent test API client creates one 3-row synthetic CSV project, one synthetic overview investigation, and one verified evidence ID, then checks initial report library is empty and saves original Quality history for comparison. The browser routing interceptor permits the UI's reviewed GETs and **exactly one** POST to `/api/projects/{id}/reports` only with an exact checked title, human-authored narrative and that one evidence ID. Any other browser mutation or external destination is rejected.
- In actual Deliver, browser chooses **General analysis** outline, confirms 0/4 headings incomplete with Save disabled, fills all four sections with explicitly human-written interpretation, confirms 4/4, selects exactly the verified evidence artifact, and performs the **one authorised Save**.
- The test verifies HTTP 201, immutable revision 1 ID and SHA-256, exact title/narrative, evidence ID and revision list. It calls actual authenticated-compatible `GET /api/reports/{id}?revision=1` and confirms saved narrative + hash; it uses **normal** `GET /api/reports/{id}/export/html?revision=1` and `GET /api/reports/{id}/export/pdf?revision=1` endpoints and checks expected filenames, real HTML headings and SHA-256, a valid PDF signature and **in-memory PyMuPDF text extraction** of all four exact section headings and analyst interpretation. It never writes export files to disk or starts Windows Save As.
- On a real Chromium page reload, the exact new report is reloaded through its read-only GET and the original narrative and title are restored. The browser reports no unexpected writes or external calls. The saved report library has exactly one revision and the original synthetic project Quality history is unchanged.
- The prior read-only [real saved-revision comparison + bounded evidence inspection test](../frontend/e2e/p2-real-http-report-comparison.spec.ts) remains a **second** distinct scenario in the same workflow. The Playwright config's explicit test list and trusted workflow path filters have been updated to include the new spec; no production React/TypeScript, FastAPI, SQLite schema, PDF renderer, report font gate or install code changed.
