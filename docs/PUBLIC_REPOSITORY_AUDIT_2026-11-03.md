## Implementation order under one-primary-phase policy
1. **Security settings with no source phase switch:** Inspect GitHub Security alerts/secret-scanning status and fork-PR workflow policy; establish non-destructive branch/ruleset protection with owner oversight. Avoid automatically invoking heavy build-e pipelines.
2. **P1 verification:** Run native Windows keyboard/scaling matrix from `docs/P1_NATIVE_ACCESSIBILITY_QA_2026-11-03.md` in the existing DEV ONLY environment; record PASS/FAIL/BLOCKED per item. Resolve true defects with focused tests, then finish Model/Predict unsaved state, cross-tab/restart and import->Quality->switch->failed-read recovery.
3. **P1 CI design only until authorised:** Introduce an isolated, read-only, branch-scoped workflow when reviewed, using pinned trusted actions, synthetic fixtures, `npm ci`, bounded Playwright, no Python/Rust installer or AI sidecars, no secrets, and no access to owner data. Validate actual hosted results when run. A workflow file alone is not evidence of a passing test.
4. **Baseline/governance after appropriate review:** Resolve `main` vs active branch, document licensing and security guidance, and plan exact dependency locking; do not rewrite branch history or silently enable untrusted release automation.
5. **Later phases:** Maintain P1 as sole active phase until its documented exit criteria are met; no gratuitous P2–P8 code or packaged distribution.
