## Research and dependency decisions

- Tauri 2 documents [WindowConfig](https://docs.rs/tauri-utils/latest/tauri_utils/config/struct.WindowConfig.html), [PathResolver](https://docs.rs/tauri/latest/tauri/path/struct.PathResolver.html) and [WebviewWindowBuilder](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html): Windows default webview storage is app-local data; config can defer window creation and Rust can construct the window from existing config and select its data directory. Use the existing app-local root, not a new browser/ folder, to preserve localStorage/preferences. Microsoft [WebView2 environment creation](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl) documents environment and registry overrides, and [environment5](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment5) documents shared browser processes and shutdown. Requested folder is not evidence of the effective folder or all browser writes. Reject unexpected overrides before creation where support permits; independently verify effective profile using supported environment interface before admitting UI work; no blanket environment redirection or policy edits. Retain explicit isolated QA override contract with a separately validated disposable root. Do not move or clear browser profiles.
- Exact dependency limitation: published frontend package-lock resolves @tauri-apps/api and cli 2.12.4; Cargo.toml uses broad v2 ranges; Cargo.lock absent from published tree. Prior native build recorded a lock digest, not resolved versions. Do not assert exact Rust API compatibility from JS package version or current docs. Establish a reviewed locked Rust dependency resolution and compile-only verification before integrating deferred WebView construction. Do not overwrite a local owner lockfile.
- Windows [reparse point operations](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-operations), [CreateFile sharing](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [Rust Windows OpenOptionsExt](https://doc.rust-lang.org/stable/std/os/windows/fs/trait.OpenOptionsExt.html), [Python 3.11 os](https://docs.python.org/3.11/library/os.html) support a no-follow, physical-identity boundary. Validate existing ancestors before creating directories; use handle-derived identity, reparse checks, link count and same volume for mutable files; reject unsupported/ambiguous roots rather than follow or delete. Mere canonicalization after mkdir is not a security boundary. Static preflight does not protect against concurrent hostile path replacement; hold appropriate directory/file handles and validate at write boundaries as subsequent source work. No OS sandbox claim.
- Ownership: use OS-held nonblocking locks, not PID files or existence of a marker. [Python msvcrt.locking](https://docs.python.org/3.11/library/msvcrt.html), [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) and [fcntl flock](https://docs.python.org/3.11/library/fcntl.html) support lock release on process/descriptor exit. Separate desktop/profile ownership and analytical writer ownership; never allow both to contend for the same exclusive lock. Backend must retain writer lease for its complete lifetime, independently of parent desktop death. A replacement process may run recovery only after old writer exits. A persistent empty lock file is not proof of ownership, never delete it to clear a stale lock. Locks coordinate cooperating processes only, not arbitrary programs or legacy versions that ignore the protocol. No privileged service or dependency required.
- [PyInstaller one-file operation](https://pyinstaller.org/en/stable/operating-mode.html) extracts before Python entrypoint; [runtime temp options](https://pyinstaller.org/en/stable/usage.html) document Windows temp selection. Keep validated worker TEMP/TMP/TMPDIR configured in Rust BEFORE spawn. Python guard cannot contain bootloader extraction retroactively. Preserve inference DLL working directory until a source-supported loader alternative is proven. Owner pipe EOF requests backend shutdown; shell must later implement a bounded cooperative drain and verified owned-worker exit, with forced owned-worker termination only on timeout, recorded as interrupted, never graceful success.

## Failure matrix and acceptance criteria

| Failure | Required behavior and test |
| --- | --- |
| Concurrent backend starts, same workspace | One owns writer lease; loser fails before DB init, no experiment marked interrupted by loser; separate roots allowed. |
| Abrupt owner exit / stale marker | Old writer lease persists while writer alive; after writer process exit OS releases lock; restart acquires existing empty marker, no PID guessing. |
| Missing/relative/untrusted roots, junctions or links | Fail closed before DB import; no write through redirected ancestor; existing wrong-type/multiple-link lock rejected. Full path-swap/physical verification remains subsequent A2. |
| Permissions/disk-full/open failure | Fixed privacy-safe startup failure; no fallback path or destructive cleanup. |
| Existing profile and projects | Same paths, localStorage and DB history, no migration/reset; verify in approved runtime test later. |
| Environment/registry profile override | Explicit valid QA path or reject unexpected override; no silent new path or policy modification. |
| Worker stop timeout or crash | Accurate interrupted state, release only owned resources; no unowned PID kill; no false clean shutdown. |
| Partial artifact publication | No destructive repair in A; Package B manifest/reconciliation retains committed references. |
| Memory pressure | No new eager model; preserve current resource limits; C and separately approved 8 GB evidence remain pending. |
