# P4 R02.5 | Original WebView2 child handles required for no-CDP FileIO

**21 November 2026 | SOURCE AND SYNTHETIC TESTS PASSED. Not a native app run or file containment proof.**

## Why this was the next necessary change

The guarded no-CDP Full Kernel-File integration ([previous step](./P4_N12_NO_CDP_STRICT_FILEIO_BRIDGE_AND_ACCEPTANCE_LIMIT_2026-11-21.md)) could collect a complete ETW event stream but did not itself require the already-developed original Windows child-handle observer or bind the private child lifetime result to the FileIO diagnostic. Without this, even a technically valid ETW FileIO event or browser command-line profile witness would lack corroboration that **every original scoped WebView2 descendant** was observed and bound to independent Sysmon GUID, ETW birth/stop and the retained original query handle. Historical seven missing original child handles remain missing. This cannot be repaired retrospectively.

## Tested implementation

[Source commit 1ed9bfe](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/1ed9bfe401dfea7251a6d2d256739c2d012a6756) in the active feature branch:

1. **Fail closed before capture:** The separate, default-off \`n12_app_lifetime --no-cdp --fileio\` path now requires \`PILOTODIN_N12_CHILD_HANDLE_CONSENT=I_APPROVE_ONE_N12_QA_CHILD_HANDLES\` **in addition** to the previously required no-CDP, lifetime and FileIO one-use consent. It invokes the existing \`n12_private_child_pipe.hosted_scope\` to enforce trusted Windows hosted push, exact source SHA/binary digest and proper first-attempt scope **before preparing the journey or starting the native session**. The normal no-CDP process-only path is not changed. Existing full-app native workflows remain disarmed.
2. **Original lifetime evidence remains private:** The existing \`ScopedQaChildHandleObserver\` and authenticated in-memory pipe retain original WebView2 handle witnesses, preserving PID, original birth and exit FILETIME, full DOS and native image, parent PID and ETW parent sequence checks, while no private raw identity is written to public reports. Its existing \`private_child_handle_diagnostic\` remains \`REVIEWABLE_ONLY\` at most, never native PASS.
3. **Reconcile FileIO scope with independent original-child inventory:** The no-CDP FileIO redacted reviewer now requires the prior independent lifetime reducer's fixed-label child receipt to have exact scope, \`REVIEWABLE_ONLY\` status, empty failed checks and verified counts matching **the full scoped WebView and WebView-network role inventory**, with both roles present, matching source SHA/binary digest and a completed positive app-lifetime report. Missing children, duplicate/unmatched witnesses, wrong role counts and ambiguous original handles leave the FileIO gate **BLOCKED**.
4. **Browser profile must match independently, without claiming effective storage:** The existing \`verify_profile_shutdown\` reviewer binds the single browser command-line \`--user-data-dir\` to the disposable UDF from Sysmon/ETW role and ancestor evidence. Only if its result is \`SOURCE_OS_CORROBORATED\`, with complete in-window descendants and the matching private-child inventory, does the FileIO diagnostic output \`browser_command_line_profile: SYSMON_ETW_BROWSER_PROFILE_COMMAND_LINE_REVIEWED\`. That label is a **browser process command-line witness, NOT verified effective filesystem write location**. \`effective_webview_user_data_folder\` remains \`NOT_VERIFIED\`.
5. **Strict FileIO facts preserved:** All \`trace.inspect_etw_files\` prohibited operations, unresolved paths, loss and unsupported operations remain unsuppressed. Even ideal mocked child and profile receipts cannot change \`file_mutation_acceptance: NOT_EVALUATED\`, \`native_N12_acceptance: NOT_EVALUATED\`, \`status: BLOCKED\` or \`full_product_tree_mutation_containment: NOT_DEMONSTRATED\`. Without full N12 calibration/positive transient write-and-restore, the blocker remains.

## Current limitations and next targeted engineering action

The source-only safeguards now require the original-child proof rather than treating a PID, profile substring or browser UDF setting as sufficient. **This does not prove a particular successful original WebView child completed a particular IRP write**, especially across process exits/PID reuse, and it does not prove all child processes or writes will be captured on the next native attempt. The existing observer polls child processes and may miss an early, short-lived child. An independently complete originally-held-child inventory, source/ETW/Sysmon clock semantics, zero loss and the positive transient control remain outstanding. No actual WebView2 startup, effective UDF storage or prohibited file destination was remeasured.

**Next and only current file-mutation engineering action:** Reuse the existing N12 same-capture write-and-restore and generated calibration fixture in this new no-CDP Kernel-File capture, including its own FileObject/IRP path evidence and before/after protected endpoints. All positive transient writes must be observed and unique, even where endpoints match. Do not grant PASS if calibration is absent, if real WebView child handle sampling is incomplete, or if the observed prohibited writes remain. After independently source-verifying the full approved protocol (including native run cleanup, temporary roots, original-owner preservation, privacy and fresh one-use scope), seek separate owner approval before running real Tauri/WebView2. Then use **actual observed file names and writers privately** to identify the minimal product-side WebView2 storage correction, followed by another separately authorized complete acceptance capture.
