## Latest verified increment: archived-project HTTP mutation guard (4 November 2026)
**Tested SHA:** [`1ac2587920cd`](https://github.com/Sonkhe-Shongwe/PilotODIN/commit/1ac2587920cd0e482102ce96a24c0b739ad220fe). **P1-M4 request-entry protection**: a project archived in another window is refused for state-changing HTTP routes even if an old tab still has its project loaded. The local authenticated `desktop_session_guard` checks the authoritative `project_lifecycle` state on POST, PUT, PATCH and DELETE calls before entering the route, including direct `/api/projects/{id}/...` and indirect `/api/experiments/{id}/{select|predict|cancel}`, `/api/investigations/{id}/{runs|autonomy/...}` and `/api/reports/{id}/revisions`. The actual project is resolved by fixed, parameterized SQL joins, not a client-supplied project hint. For archived projects, the response is HTTP 409, with a clear restore instruction; no downstream mutation executes. `GET` remains unchanged; project import and explicit lifecycle rename/restore still function. In desktop-session mode, a missing/incorrect secret fails HTTP 401 **before** archive status is inspected.

**Verified exact scope:** [backend lifecycle CI #41840614063](https://github.com/Sonkhe-Shongwe/PilotODIN/actions/runs/41840614063), **14/14 disposable pytest PASS** (backend tested on source ancestor `3dd784f47153`, production backend unchanged afterward); [frontend #41840976435](https://github.com/Sonkhe-Shongwe/PilotODIN/actions/runs/41840976435) **145/145 Node, TS/Vite build, 5/5 Chromium PASS**; [real HTTP #41840976488](https://github.com/Sonkhe-Shongwe/PilotODIN/actions/runs/41840976488) **4/4 independent Uvicorn+Chromium scenarios PASS**, including the synthetic two-tab archive followed by actual 409 denials on Quality commit, investigation creation, target context and report creation, then Restore. Original user datasets and Windows installed app untouched.

**Important limitation, not a waiver:** This is a **request-entry check**, not an end-to-end SQLite transaction freeze. An already-started write could theoretically race a concurrent archive after the preflight. It does not cover direct Python function calls/background worker internals or every non-HTTP write. Prior to any irreversible Delete, require centralized commit-time write checks, authoritative ownership inventory, durable exclusion/journal/quarantine and crash recovery. P1 native owner gates, real multi-Window WebView2, full resource, scaling and Narrator checks remain **OPEN**. No DELETE endpoint is added.
