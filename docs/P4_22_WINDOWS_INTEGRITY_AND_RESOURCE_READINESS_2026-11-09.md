## New read-only Windows probe, with honest limits

**Opt-in PowerShell script:** [`qa/p4_native/Measure_P4_Native_Readiness.ps1`](../qa/p4_native/Measure_P4_Native_Readiness.ps1).

1. `Baseline`: requires explicit existing `-OriginalExe` and `-OriginalData` paths plus an external `-EvidenceDir`. Reads SHA256 of the original executable and a **recursive aggregate tree SHA256** of every ordinary file using the hash of each relative path, SHA256 of each file content and file size; records aggregate file count/bytes. Refuses symlink/reparse points inside source data instead of silently following or skipping them. Creates only `baseline.json` **outside** original data and app installation directories; never overwrites existing evidence.
2. `Verify`: repeats the original executable and data-tree snapshot, requires an **independently verified expected QA desktop EXE SHA256** and exact QA EXE, checks equality, and writes `verification.json` in the same external evidence directory. Any old-file mutation, original EXE mutation or QA EXE hash mismatch is reported **FAIL**; a file/read error stops the check. Does not trust an install filename or infer source identity from an arbitrary user-provided expected hash.
3. Optional `-Samples N -IntervalSeconds S` at `Verify`: on Windows, reads system free/total physical memory and sums **currently discoverable QA-rooted process descendants** by observed Windows process parent IDs, recording approximate private/working-set totals across N samples. This is labelled **PARTIAL_OBSERVATION** only, not peak RSS, a sustained 8 GB test, an offline test, or proof that detached/reparented sidecars and WebView2 processes were included. With no QA process observed the status is **NOT_TESTED**; with `-Samples 0`, **NOT_TESTED**. System hardware details are summarized without exporting process command lines, personal file names or file contents.
4. The probe **never starts or stops an app**, executes an installer, edits original local project files or SQLite, calls a backend endpoint, trains a model, downloads models, accesses cloud services, or declares release/operational suitability. The only writes are `baseline.json` and `verification.json` under the explicit external evidence directory. Operators should **close the old app and prevent concurrent updates** before baseline and verification: two file hashes are not an atomic filesystem snapshot, and concurrent normal writes would cause a mismatch or inconclusive result.

**Privacy:** Raw source filenames, source paths, contents, database pages and model files are NOT copied into the JSON. The aggregate tree digest, file count, byte totals and system memory totals may still be sensitive context; the owner should inspect before sharing. A SHA256 comparison does not independently verify origin authenticity or prove recovery from backups.

### Non-actionable usage illustration for a future authorised session

Example only; **do not execute before the owner authorises the current-source Windows milestone**. Verify actual filenames, installation paths and independently sourced QA hashes rather than copying a stale SHA:

```powershell
$probe = '.\qa\p4_native\Measure_P4_Native_Readiness.ps1'
$oldExe = Join-Path $env:LOCALAPPDATA 'pilotODIN\pilotodin-desktop.exe'
$oldData = Join-Path $env:LOCALAPPDATA 'com.pilotodin.studio'
$evidence = Join-Path $env:USERPROFILE 'PilotODIN-P4-QA-Evidence'
# Only BEFORE a separately authorised Windows QA installation:

# Only AFTER independent current-source installer and installed-EXE hash verification:
```
